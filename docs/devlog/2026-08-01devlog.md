### 19:57 - Phase 0 Steps 0.1-0.6: project skeleton, pinned deps, governance docs, public repo

Started a new one today. vanlife-dashboard, a native desktop app to help sort raw vanlife documentary footage before it ever gets near DaVinci Resolve. Different from the main SEEKERS_GHOSTS build in that this one lives in its own public repo and its own venv, meant to actually get used on real footage, not just prove out an architecture.

Laid out the skeleton, app folder, ui subfolder, data folder with a proxies cache, docs with a devlog folder, then `python -m venv .venv` right at the root. Wanted this one fully isolated from whatever's floating around on system Python.

Checked PyPI live for every package before pinning it instead of trusting a floor version. PySide6 6.11.1, python-dotenv 1.2.2, PyYAML 6.0.3, faster-whisper 1.2.1, psutil and nvidia-ml-py for a resource watchdog a few phases out. PySide6's addons package alone was almost 170MB.

The git situation took more thought than expected. This project sits physically inside the SEEKERS_GHOSTS working tree but needed to be its own repo entirely, public, separate history. SEEKERS_GHOSTS's own gitignore had to learn to ignore its own subfolder, one line, confirmed with git check-ignore that it actually took.

AGENTS.md and INSTRUCTIONS.md next, modeled on the ones I already run for SEEKERS_GHOSTS. Thirteen phases mapped out from this governance step through canvas boards, local AI tagging, and the Resolve export at the end.

Repo went up clean, TheSeeker713/vanlife-dashboard, public, main. Fetched it back down after to make sure origin actually had what I thought it had. It did.

Phase 0 closed. Design and scaffolding next, first time this thing looks like something instead of folders and markdown.

### 20:27 - Phase 1 Steps 1.1-1.3: window shell, theme, menu bar, layout persistence

Got the actual window up today.

Theme first, light by default like I'd already decided. Small palette module so the tag colors live in one place instead of getting hardcoded everywhere later.

Then the shell. MainWindow, dock widgets for Browser, Timeline, Chat, Canvas, Metadata Viewer, a Resource Monitor hidden until asked for, Player in the center. Full menu bar, most of it disabled since those phases haven't landed, still satisfying laying out the whole roster even half-inert.

Got asked partway through if the side panels could be expandable. Fit naturally into what I was already building. Each panel got a header button that hides its siblings and gives that one the room. Took longer than it should have: turned out my layout wasn't pinning the header to the top, no explicit stretch factors, Qt was placing it wherever the placeholder content below left room. Fixed with explicit stretch and a fixed header height.

Found a real problem while I was in there too, not cosmetic. Clicking near a panel's title bar was hitting Qt's own close button, panel just vanished with no way back short of the View menu. Movable and floatable now, not closable that way.

Spent a while chasing which tab lands frontmost in a grouped panel before realizing it was stale QSettings from my own earlier test runs, not a real bug. Cleared them, dock creation order controls it fine after that.

Wrote a real persistence test, not just eyeballing it. Resize, hide a panel, close, reopen, check it came back. It did.

Phase 1 done, committed, pushed, verified against remote. Backend foundation next.
