### 19:57 - Phase 0 Steps 0.1-0.6: project skeleton, pinned deps, governance docs, public repo

I started a new one today. vanlife-dashboard, a native desktop app to help me sort raw vanlife documentary footage before it ever gets near DaVinci Resolve. This one's a little different from the main SEEKERS_GHOSTS build because it lives in its own public repo, its own venv, and it's meant to actually get used on real footage, not just prove out an architecture.

First thing I did was lay out the skeleton under `_test_project\vanlife-dashboard\`, app folder, ui subfolder, data folder with a proxies cache, docs with a devlog folder. Then `python -m venv .venv` right at the project root. I wanted this one fully isolated from whatever's floating around on system Python, and honestly it felt good to start clean instead of inheriting a pile of packages I didn't ask for.

Before I touched requirements.txt I actually went and checked PyPI live for every package I was about to pin. PySide6 6.11.1, python-dotenv 1.2.2, PyYAML 6.0.3, faster-whisper 1.2.1, and then psutil and nvidia-ml-py for a resource watchdog I'm planning a few phases out. Pinned every one of them exact, no loose `>=` floors. Installed clean into the venv, ran pip freeze after to confirm every version matched what I pinned. PySide6's addons package alone was almost 170MB, that download took a minute, but everything landed where it should.

The part that took more thought than I expected was the git situation. This project sits physically inside the SEEKERS_GHOSTS working tree, but it needed to be its own independent repo, public, separate history, separate everything. That means SEEKERS_GHOSTS's own gitignore had to learn to ignore its own subfolder, which is a weird thing to stare at for a second before it clicks. Added one line, `_test_project/vanlife-dashboard/`, and confirmed with git check-ignore that it actually took. Wrote the inner project's own gitignore too, venv, sqlite files, the proxy cache, the log file, all excluded from that side.

Wrote AGENTS.md and INSTRUCTIONS.md for this project next, modeled directly on the ones I already have for SEEKERS_GHOSTS. Same phase and step discipline, build then test then verify then commit then push then devlog, stop at the end of every phase and wait for me before continuing. INSTRUCTIONS.md ended up covering all thirteen phases I mapped out in planning, from this governance phase all the way through canvas boards, local AI tagging, transcription, and the DaVinci export at the end. Feels like a lot written out like that, but every phase is small on its own.

Then the actual repo. Confirmed with myself in chat before doing anything public facing, TheSeeker713/vanlife-dashboard, public, main branch. git init, first commit with the skeleton and governance docs, then `gh repo create` with push in the same command. Watched it land on GitHub, fetched it back down to make sure origin actually had what I thought it had. It did. Small relief every time that check comes back clean instead of surprising me.

Pushed the SEEKERS_GHOSTS gitignore change back to that repo too since it's routine, no separate approval needed for that one per my own rules there.

Good stopping point. Phase 0 is closed out, everything verified against real state instead of just trusting a green exit code. Next phase is the design and scaffolding pass, getting the actual window shell up with every panel placed before I start wiring real behavior into any of them. Looking forward to that one, it's the first time this project will actually look like something instead of just being folders and markdown.
