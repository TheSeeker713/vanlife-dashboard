### 20:48 - Phase 1 redo: page-bar, drawers, dark-first theme

Had to eat some humble pie today. Pulled up the Phase 1 shell I built yesterday for a fresh look and just didn't like it. At all. Six empty grey boxes with placeholder text floating dead center in each one, a tab strip that landed at the bottom of its group instead of the top, a Timeline panel taking up as much space as the Player with nothing in it yet. Read like a generic IDE shell, not a video tool.

Went back to planning instead of diving straight into code. Built a click-through mockup in plain HTML and CSS first, no Qt involved. Cheap to iterate on, easy to react to. Pulled up two references while building it: DaVinci Resolve, which I use daily, and Morphic Studio, an AI creative tool with a canvas mode I'd heard of but never actually looked into. Its whole pitch is a big spatial Figma-like canvas treated as its own dedicated space rather than a cramped side panel. Reshaped a lot of my thinking.

The mockup went through a few rounds. Wanted the panels to actually feel compartmentalized and easy to reach, the clip browser able to shrink into a drawer, sit next to the viewer, or get maximized when needed. Genuinely different interaction model than a static docked panel, so built it that way, three real states.

Once it was actually working, brought the design back into the plan file and INSTRUCTIONS.md, panel names, directory layout, every phase reference. Tedious but a build spec that quietly disagrees with itself is worse than useless.

Dropped QDockWidget entirely for the rebuild, felt like giving something up at first since the expand and collapse logic already worked in the old version. But floating and arbitrary redocking was never what this needed, Resolve and Morphic don't work that way either. Built a reusable Drawer component instead, one class for both the horizontal collapse-to-strip behavior on Media Bin and the vertical collapse-to-header on Chat and Metadata, plus a maximize state just for Media Bin.

Dark by default this round too, reversing my own earlier light-first call, the mockup next to Resolve's actual UI made the case for itself. Both themes built together from one shared palette this time.

Smoke test passed clean on the first real run, which almost never happens and made me suspicious enough to double check it wasn't just testing the wrong things. It was fine. Clicked through everything myself after: maximize, restore, collapse to a strip, page-bar switching, theme toggle with no flash of unstyled anything. Closed the app and reopened it and it came back exactly where I left it. That last check is the one I actually trust most.

One glyph rendered as a literal parenthesis in the default font, swapped to plain triangles and it cleared up.

Saved a copy of the mockup into docs/design/ since it drove real decisions here and shouldn't evaporate with my scratchpad.

Shell finally looks like it belongs next to Resolve. Backend foundation next.

### 21:08 - Quick correction: light theme is the real default

Flipped back within the hour. Talked myself into dark-by-default a few hours ago and it was the wrong call, light stays default, dark's an optional thing you reach for. Pulled the icon off the page-bar, left the toggle where it already lived in the View menu, didn't even need to build anything new for it.
