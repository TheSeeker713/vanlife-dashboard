### 20:48 - Phase 1 redo: page-bar, drawers, dark-first theme

Had to eat some humble pie today. Pulled up the Phase 1 shell I built yesterday for a fresh look and just didn't like it. At all. Looking at it again with clear eyes I could see why: six empty grey boxes with placeholder text floating dead center in each one, a tab strip that somehow landed at the bottom of its group instead of the top, and a Timeline panel that took up as much space as the Player even though it had nothing in it yet. It read like a generic IDE shell, not a tool for editing video.

So I went back to planning instead of just diving straight back into code. Built an actual click-through mockup in plain HTML and CSS first, no Qt involved yet. Turned out to be exactly the right call, cheap to iterate on, easy to react to. Pulled up two references while I was building it: DaVinci Resolve, which I've got installed and use daily, and something called Morphic Studio, an AI creative tool with a canvas mode I'd heard about but never actually looked into. Had to go research that one properly instead of guessing, turns out its whole pitch is a big spatial Figma-like canvas treated as its own dedicated space rather than a cramped side panel. That single idea reshaped a lot of my thinking.

The mockup went through a few rounds. First pass I liked the direction but wanted the panels to actually feel compartmentalized and easy to reach, specifically wanted the clip browser to be able to shrink into a drawer, sit next to the viewer, or get maximized when I needed it. That's a genuinely different interaction model than a static docked panel, so I built it that way: three real states, not two.

Once I was actually liking it, I brought the design back into the plan file. Rewrote the whole design section, updated the directory layout, renamed browser_panel.py to media_bin_panel.py in my head even before I renamed the actual file, walked every phase in INSTRUCTIONS.md that referenced the old panel names and fixed them one at a time. Tedious but necessary, a build spec that quietly disagrees with itself is worse than useless.

Then the actual rebuild. Dropped QDockWidget entirely, which honestly felt like giving something up at first since I'd already gotten the expand and collapse logic working nicely in the old version. But QDockWidget's floating and arbitrary-redocking behavior was never what this app needed, Resolve and Morphic don't work that way either, panels have fixed roles and just resize or collapse in place. Built a proper reusable Drawer component instead, one class handling both the horizontal collapse-to-a-strip behavior for Media Bin and the vertical collapse-to-header behavior for Chat and Metadata, plus a maximize state just for Media Bin since that's the one panel that actually needs to take over the whole page sometimes.

Dark theme by default this time too, reversing my own earlier call. I'd decided light-first, dark-later a while back to keep scope down, but seeing the mockup next to Resolve's actual dark UI made the case for itself, this app sits right alongside Resolve on the same desk. Built both themes together from one shared palette instead of half now and half later.

Smoke test passed clean on the first real run, which almost never happens and made me suspicious enough to double check it wasn't just not testing the right things. It was fine. Took real screenshots after that and clicked through everything myself: maximize hides the other panels and gives Media Bin the whole page, click it again and everything comes back exactly where it was. Collapse slides it down to a thin strip on the edge. Page-bar switches cleanly between Sort and Canvas with the active tab highlighted correctly. Theme toggle swaps the whole stylesheet instantly with no flash of unstyled anything. Closed the app, reopened it, and it came back exactly where I left it, Canvas page, dark theme, same layout. That last one is the check I actually trust most, a lot of bugs like to hide specifically in the space between closing and reopening.

One tiny glyph issue along the way, the angle-bracket collapse icon I picked first rendered as a literal parenthesis in the default UI font. Swapped to plain triangle characters instead and it cleared right up. Small thing, but it's the kind of small thing that would have looked broken to anyone who wasn't looking for it specifically.

Saved a copy of the approved mockup into docs/design/ before wrapping up, since it drove real structural decisions here and shouldn't just evaporate when my session scratchpad clears. Feels like the kind of artifact future me is going to want to reference again.

Good place to stop. The shell finally looks like it belongs next to Resolve instead of looking like a form builder. Next up is the actual backend foundation, database and the path allow-list and the sys.path bridge over to SEEKERS_GHOSTS. Less to look at, but everything after it depends on getting that part right.

### 21:08 - Quick correction: light theme is the real default

Barely had the pixels dry on that last entry before I second-guessed one piece of it. I'd flipped to dark-by-default during the redo and reasoned my way into liking it, but sitting with it a little longer I realized that was backwards: light needs to stay the default, dark is a user-optional thing you reach for in settings, not something pushed on you the moment the app opens. That was my own call to make and I made the wrong one the first time.

Quick fix. Swapped the default in main_window.py, pulled the little theme icon off the page-bar entirely since a headline icon button next to Sort and Canvas was treating theme switching like a primary feature instead of a preference, and left the toggle sitting right where it already existed in the View menu. Turns out I didn't even need to build anything new for this, the menu action was already there, I just had to stop competing with it visually.

Fixed the QSS header comments too so they actually say which one is default instead of lying about it, and swapped the fallback values in settings restoration. Ran the smoke test again with the assertions flipped, clean pass, then watched it with my own eyes: opens light, View menu has Toggle Theme sitting right under the panel checkboxes, click it and dark comes in clean.

Small correction, but glad it happened now instead of three phases from now when reversing a default gets more expensive.

While I was in there I also tightened up how a phase actually gets closed. Wrote a proper close-out sequence into INSTRUCTIONS.md: finish the steps, then a real audit pass across the whole project before anything gets committed, not just the newest file, then tests again, one commit, the devlog entry, and for anything with an actual UI, a checklist I run myself with my own hands before the next phase starts. Not a report I accept. Something I click through.

Put both of these into .claude/rules/ too, devlog-voice.md and phase-protocol.md, so they're not just paragraphs in a file that only matter if someone remembers to reread it first.

First real test of the new checklist idea is Phase 1 itself, retroactively, since it shipped before any of this existed. Fifteen items, wrote them into INSTRUCTIONS.md as the worked example.
